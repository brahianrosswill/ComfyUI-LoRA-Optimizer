# H3 FATE evaluator: loading fixed locally, controls passed, ranking unqualified

This continues the [coverage/preflight investigation](2026-09-09-h3-synchformer-coverage.md). It adds an isolated evaluator, not a production merge-mode or autotuner change. The user's existing authorization covers local setup and testing on already-rated clips; no held-out media or external uploads were used.

## A real loading failure, not just a warning to ignore

The pinned [FATE source](https://github.com/guankaisi/FATE/tree/beae95aeb6f72cf1751d06d1428931016a7a1867) uses a custom model with `audio_encoder`, `video_encoder`, `audio_head` and `video_head` roots. The public base checkpoint nests those under `audio_model` / `video_model`.

A CPU-only reproduction of its default `PeAudioVideoModel.from_pretrained` call returned a model with **610 missing keys, 859 unexpected keys, and zero direct matching keys** in the tested Transformers 5.0.0 environment. The loader explicitly reported newly initialized missing parameters. This model was discarded without a forward pass. Its full loading report is retained; a first diagnostic attempt also remains preserved because the library's logging-handler cleanup assertion interrupted receipt creation, not model loading.

The private research loader therefore maps exactly four explicit prefixes, verifies every required shape, and uses strict state loading. All **610 required base tensors** match the pinned checkpoint values exactly. The remaining 249 checkpoint keys belong to components absent from this custom scoring model; the complete exclusion list is recorded, not silently ignored. All **134 adapter tensors**, including its six saved head tensors, match exactly after lossless BF16-to-FP32 promotion where applicable. No required parameters or buffers remain uninitialized. No LoRA merging, pickle loading, training-state loading or remote model code is involved.

This is an audited **FATE-derived local evaluation path**, not a verified reproduction of the paper's training setup or published results. The default-loader failure is demonstrated for these specific pinned artifacts and dependency versions; it does not establish how the authors prepared their private training checkpoint.

## Isolated setup and timing contract

The new private Python 3.12 environment uses PyTorch 2.8.0+cu128, Transformers 5.0.0, PEFT 0.18.0 and timm 1.0.24. The actual imports require newer APIs than the advertised Transformers >=4.53 lower bound. The chosen version matches the base config's 5.0.1.dev0-era APIs. See [pinned requirements](h3-fate-requirements.txt); the complete resolved package inventory is in the receipts. Existing ComfyUI, Qwen and Synchformer environments were not modified.

Base and adapter safetensors total **3,397,544,440 bytes** and match the previously inspected public SHA-256 values. Metadata and safetensors headers were inspected before weights were loaded.

The [prospective policy](data/2026-09-09-h3-fate-controls-policy.json) fixes A05/A09 only, nine conditions per clip, two A05 repeats, and three two-second windows: [0,2), [1.5,3.5), [3,5). The final four source frames are excluded. Overlapping windows are not independent observations.

The first attempt rejected source metadata before any forward pass: the native audio is **32 kHz**, not the initially assumed 48 kHz. The [recorded amendment](data/2026-09-09-h3-fate-controls-amendment-02.json), frozen before scores existed, specifies arithmetic stereo downmix followed by explicit torchaudio sinc/Hann 32→48 kHz resampling. It does not change any conditions, windows or gates. Both sources were then validated before loading CUDA weights. Original native and resampled PCM hashes/counts are retained.

Each window uses all 48 native 24 fps frames, with the official processor's bilinear 336×336 resize and no crop. Audio is exactly 96,000 samples; no reflected padding is needed. All masks must be valid. Unsupported padded inputs are rejected before reaching the previously reproduced alignment edge case; the supported alignment calculation is unchanged.

Actual output is 50 paired 1024-dimensional feature vectors. Video features are expanded with the upstream floor/nearest index map from 48 to 50 positions. Comparing nominal coordinates gives video-minus-audio feature-grid differences from **−40 ms to 0 ms**. These are not independently observed sound/contact onsets: the embeddings have temporal context. The harness records the mapping rather than claiming exact event timing.

## Frozen control results

All **20 cases / 60 forward passes** completed using FP32 parameters and BF16 CUDA autocast. Scores below are raw cosine-similarity averages, not probabilities or human ratings.

| Condition | A05 | A09 |
| --- | ---: | ---: |
| Original | 0.160499 | 0.169194 |
| Audio delayed 750 ms | 0.131592 | 0.155235 |
| Audio advanced 750 ms | 0.156050 | 0.175459 |
| Delayed 125 ms | 0.159380 | 0.162933 |
| Advanced 125 ms | 0.162109 | 0.166494 |
| Delayed 80 ms | 0.157614 | 0.172955 |
| Advanced 80 ms | 0.161916 | 0.174712 |
| RMS-envelope-following 440 Hz replacement | −0.042892 | −0.004862 |

For the already-rated stronger-sync control A05, both gross shifts and the tonal replacement score below the original by more than the predeclared 0.0001 margin. Both repeated full diagonal sequences are exactly identical, with identical input hashes. Muted inputs produce raw diagnostic scores (0.048491 / 0.053495), but the harness reports synchronization as **unassessable**, not as a learned silence judgment. The tonal intervention changes several audible properties; it is not a pure semantic-isolation experiment.

These necessary gates pass, but contrary evidence is already visible:

- A09's original score exceeds A05's, whereas R1 rated A05 synchronization 4 and the shared A09 source 1 / 2 in the two pairings. These are one person's labels, not consensus.
- Small shifts are not monotonically penalized. Some improve scores. An imperfect source can benefit from a shift, so these controls do not establish a correct physical correction.
- In A05's first two-second window, advancing audio 750 ms **raises** the score from 0.112046 to 0.158914 even though the three-window average falls. Passing the aggregate gate does not validate local contact/sound assessment.

Do not turn these scores into an autotuner reward, fit weights to R1, choose a favorable window after seeing results, or claim an H3 merge improvement. The [paper](https://arxiv.org/abs/2608.01310) itself reports only modest average per-clip agreement and does not validate H3; this local test cannot remove that limitation.

## Verification and next bounded step

The independent CPU auditor does not import the FATE model or inference runner. It reconstructs native decoding/downmix/resampling, every control waveform, frame selection, resize/normalization and masks. All **180 input-tensor records** match exactly. It also reconstructs all 60 window scores from the saved normalized embeddings using a separate double-precision contraction, verifies the aggregates and repeats, and checks the actual temporal mapping. No GPU inference was repeated for this audit.

**142 focused evaluator tests passed** (37 new FATE tests plus 105 existing evaluator/coverage tests). Peak allocated GPU memory was 2,762,175,488 bytes, approximately 2.57 GiB. The process exited, the existing ComfyUI queue remained empty, and GPU usage returned to approximately 2.69 GiB system usage. No production source, prior frozen evaluator runner, installed node pack, version, commit or push changed.

The [checkpoint](data/2026-09-09-h3-fate-checkpoint.json) pins setup, failed attempts, source, policies, loading probes, the 60-window run and its independent audit.
